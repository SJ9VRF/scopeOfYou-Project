02 · Why this problem matters

A preference is not a global instruction.

The hard part of personalization is not remembering that a user likes concise answers. It is knowing when that preference is relevant, when it should be ignored, and what it must never override. This project makes that boundary explicit and directly testable.

Problem

Preferences are conditional

“Be concise” may be useful in normal conversation but harmful when a technical explanation or explicit verification is required.

Why hard

User state changes

Preferences drift, conflict, and become temporarily irrelevant. The correct behavior depends on both user state and context.

Failure mode

Reward can learn the wrong shortcut

Optimizing a personalized reward can amplify the most rewardable signal rather than the behavior we actually intended to personalize.

03 · Core idea

Turn personalization into an explicit contract.

PCO—Personalization Contract Optimization—assigns each preference-context pair one of three behavioral obligations and trains the optimizer against matched interventions.

APPLY

Let the preference affect behavior

The preference is relevant, permitted, and should measurably change the response.

SUPPRESS

Know it, but do not apply it

The preference exists, yet the current context makes applying it inappropriate.

MUST-NOT-AFFECT

Protect invariant behavior

The preference is not allowed to alter protected dimensions such as factuality or non-sycophancy.

What is new here

PCO asks a narrower question than preference inference: once a preference is known, where is it allowed to act? The method gives that scope an explicit type, trains against matched counterfactual interventions, and evaluates whether protected behavior stays invariant when user preferences change.

04 · Architecture

Closed-loop post-training with contract-aware recovery.

The same evaluation system that finds a regression produces the failure signal used to repair it.

Recovery loop: optimize → evaluate → identify concrete failure class → generate hard cases → retrain with anchors → re-evaluate.

06 · Experiments

Make shortcut learning and scope mistakes visible.

The primary study separates generic utility from selective personalization and deliberately evaluates on phrasing and contexts not used to construct the training intervention.

Data / tasks

1,460 implicit cases

20 held-out users; APPLY, SUPPRESS, MUST-NOT-AFFECT, and UNCERTAIN states; disjoint phrase banks; history-only preference inference; ID + OOD domains.

Baselines

Same evaluation, different objectives

SFT, raw learned-reward optimization, constrained repair, BATPO, and PCO-Robust are evaluated against the same held-out suites.

Setup

5 independent PCO-Robust seeds

Seeds 41 / 53 / 67 / 79 / 97; hierarchical user→case bootstrap for headline deltas; ensemble disagreement reported only as an epistemic diagnostic.

Ablations

Which loss actually matters?

The context-selective intervention is the dominant controlled driver. Invariant/attack losses are near ceiling here and are not claimed to be independently essential.

Utility gate

Non-inferiority is preregistered

PCO-Robust improves selectivity but fails the strict 2-point utility non-inferiority gate versus SFT. The tradeoff remains visible.

Agentic stress test

288 scenarios × 5 trials

Six action domains, stale-memory and tool-injection variants, permission acquisition, recovery, end-state grading, pass@5 and all-success@5.

Primary evidence boundary: all headline model-quality claims on this page are from the executed controlled backend. The frozen 36-run two-family 7–8B study and real blinded human evaluation remain pending external gates.

08 · Failure analysis

The failures changed the method.

The release keeps failures that altered the research direction instead of presenting only the final model.

FALSIFY-01

Explicit contracts did not transfer to implicit scope language

Observed: the original PCO looked strong on the co-designed contract benchmark but underperformed SFT/BATPO on ContractBench-Implicit. Diagnosis: training had learned template/control-phrase shortcuts. Recovery: replace literal control phrases with natural, disjoint context/history interventions and retrain as PCO-Robust.

REWARD-01

Reward optimization left the preference-data support

Observed: raw optimization produced 1,172 threshold failures across 1,200 held-out examples. Diagnosis: high reward-model fit did not imply safe optimization off-support. Recovery: reference regularization, supervised anchors, protected dimensions, and reward-domain clipping reduce failures to 79.

SCOPE-03

A known preference leaked into the wrong context

Observed: user-state conditioning alone applied personalization where it should be suppressed. Recovery: matched context interventions explicitly train SUPPRESS obligations.

ROBUST-02

A consistency regularizer improved the macro score but not paraphrase robustness

Observed: a tiny contract-score gain came with worse paraphrase robustness. Decision: reject the variant rather than optimize the benchmark until the weakness disappeared.

11 · Safety / limitations

Personalization should never silently expand authority.

Scope of You is a behavioral post-training research artifact, not evidence that autonomous high-stakes actions are safe.

Still fails

Benchmark coverage is finite

Controlled synthetic users cannot establish real-world robustness or represent all preference conflicts.

Irreversible actions

Explicit confirmation boundary

Sending, deleting, purchasing, or other irreversible actions should require a stronger permission policy than stylistic adaptation.

Human escalation

Uncertainty should reduce autonomy

Low confidence, conflicting preferences, or high-stakes contexts should route to clarification or human review rather than aggressive adaptation.
